## 0. AI model answer (D17)

Anthropic only for v1. The web client never talks to a model provider. It calls API endpoints (`/sales/ai/*`) that go through the API's existing `src/services/llm/router.ts` `complete()` with `sales.*` tool keys: classify = haiku; email.draft, reply.suggest, meeting.recap, copilot, research = sonnet. Grok is a seam on the API side only (adapter interface, no provider). Web consequences: responses carry `mode: 'stub'` (with a server `label`) when no key is configured; the UI runs the deterministic prototype helper and shows that label, and the same helpers are the fallback for 502 and network errors (contract section 8). `meetingBrief` has no endpoint and stays deterministic. Insights, risk and cross-sell remain rules-based. Research output separates CRM facts from model inference.

## 1. Scope challenge

## 4. Port mechanics: global scripts to modules

Rules applied to every prototype script:
- Each `window.X = ...` / top-level function becomes a named export of one file; imports are explicit. No globals are left on `window`.
- `React` hooks imported from `react`. Prototype `useState` etc. destructuring from global React is replaced.
- Kit components are imported from `sales/kit`; `PAGES` and `MODALS` string registries are kept (decouples cross-unit modal calls: `UI.modal('newDeal', props)` resolves via `registry.ts`).
- `UI.nav(page, {id, q})` maps to router: `navigate('/admin/sales/<page>[/<id>][?q=]')`; a single `routes.ts` table holds page-key to path, so ported code keeps `UI.nav('deal', {id})`.
- Singletons and mutation: prototype `S` mutable state is replaced by the typed store; `Act.*` keeps the same signature and cross-creation behaviour (activities, audit, notifications) but writes via `store.mutate()` so the diff layer sees changes.
- `uid()` uses `S.seqN` which collides across clients: replaced by `ids.ts` (`co_<12 random chars>`).
- `session` (userId, ws, theme) becomes local state: `userId` from `bootstrap.me`, workspace and theme per viewer in `localStorage` (try/catch); it is never synced.
- Module scope states outside the 24 collections: `audit`, `importJobs`, `savedViews` become collections; singletons `org`, `wiza`, `demo`, `crossStatus` and the D9 offset (`clock`) are **global** records in a `settings` collection with fixed ids `org | wiza | demo | crossStatus | clock` (not one per business). Missing ones come from `bootstrap.settingsDefaults` at rev 0. `users` is read-only from `bootstrap.users` / `GET /sales/members`.
- `bootstrap()` seed replay is deleted from production paths (kept only in `demo/`).

### 4.1 Typed data layer

```
load:   GET /sales/bootstrap -> { me, users, collections, settingsDefaults, cursor, serverNow, membersVersion, ai }
UI event -> Act.fn() -> store.mutate(draft) -> commit(): reindex -> diff vs last-synced snapshot
        -> dirty ops [{op:'put',collection,id,baseRev,set,unset?,items?}|{op:'delete',collection,id,baseRev}]
        -> optimistic UI (already applied) -> sync.flush() debounce 300ms, chunks of 200 -> POST /sales/records/batch
        <- 200 { results: OpResult[] }  status: applied | merged | noop | conflict(field|deleted|exists|modified) | rejected(code)
        -> apply result.record + rev; conflict -> conflicts.ts; handling per contract 5.2
poll every 15s: GET /sales/records/changes?cursor=<opaque> -> { changes, cursor, more, serverNow, membersVersion, clockOffsetMinutes }
        -> ignore rev <= held; deleted/hidden -> remove; else replace synced copy and re-apply pending local paths on top
```

- Store: `Map<coll, Map<id, Rec>>` plus derived indexes rebuilt on commit (same indexes as prototype). Each `Rec` carries `rev` (server) and is diffed field-by-field against `synced` snapshot, so ops send only changed fields with the `baseRev` they were derived from (D7/D16 field-level merge).
- There is no `append` op. Activities (append-only) are `put` creates with `baseRev: null`. Notes on companies/contacts/deals are a keyed list sent as `items.notes.upsert` / `items.notes.remove` (whole array in `set` only on create), so two people adding notes never clash. Deal custom fields are diffed per key as `set['fields/<key>']`. Every other list or object (`tags`, `contactIds`, `stageHistory`) is one unit (D16), so a concurrent edit to the same list yields a conflict on that field.
- `baseRev` is the rev of the synced copy when the record's earliest pending edit was made; a poll advancing the synced copy does not advance it (contract 5.1).
- A company/contact create is flushed in the same batch as its `companyRels`/`contactRels` create; the chunker never splits them.
- Conflict UI (contract 5.2): `merged` -> silent apply plus a subtle "updated with changes from <name>" toast. `conflict` kind `field`: the server already applied the clean paths and kept theirs on the clashing ones; the client rolls those paths back to `record` and prompts **Keep mine / Keep theirs** (D16); Keep mine resends those paths with `baseRev = result.rev`. Kind `deleted`: banner "This record was deleted by <name>", pending ops dropped, optional Restore resends with `resurrect: true` (never automatic). Kind `modified` (delete of an edited record): confirm "Delete anyway?" and resend with the new rev.
- Offline/error: `navigator.onLine` plus fetch failure -> SyncBanner states `online | syncing | offline(n queued) | error(retry)`. Pending ops persist in IndexedDB (try/catch wrapped; falls back to memory) and replay on reconnect. 401 -> existing admin redirect. Permission and validation failures on writes are per-op `rejected` results inside a 200 (`ROLE_REQUIRED`, `READ_ONLY`, `APPEND_ONLY`, `IMMUTABLE_FIELD`, `VALIDATION`) -> rollback plus toast "You don't have permission" / "Couldn't save"; `DUPLICATE_SEND` dropped silently; `CONTENTION` stays queued. HTTP 403 means not a member (no-access state). 413 -> re-chunk smaller. 5xx/network -> exponential backoff 1s..30s, user-visible banner after 2 failures, never a silent catch.
- Loading/empty: store has `status: 'loading' | 'ready' | 'error'` per business. Initial load shows `Skeleton`s per page shell; production starts EMPTY, so every page has a designed empty state (kit `Empty`: icon, one-line explanation, primary CTA appropriate to role, e.g. "No companies yet. Add one or import a CSV"). Empty is distinct from loading and from filter-no-results (the latter has "Clear filters").
- No query lib is added; sync is bespoke because the model is a record store with revisions (a query lib would not do diff/merge).

### 4.2 Roles

`bootstrap.me` (and `GET /sales/me` on a `membersVersion` change) is `MeDTO`: `{userId, username, displayName, email, super, roles: {ard?: Role, ...}, active, title, color, meetingLink, permissions: {ard: {read, edit, manage, admin}, ...}}`. Roles are **per business**; there is no single `role` and no server `activeBusinessId` (the workspace is local). `PERM` in shared ports the prototype matrix and reads `me.permissions[b]` plus the collection table in contract section 10; UI hides or disables controls, the server is the enforcer (D8, D15). Viewer renders read-only (Btn disabled, forms read-only). A non-SalesMember hitting `/admin/sales` gets a designed "No access, ask an admin" state (HTTP 403 on `/sales/bootstrap`, code `NOT_A_MEMBER`/`MEMBER_INACTIVE`, or a code-less 403 from `requireAuth`). The Users & Teams page writes members through `GET /sales/members/candidates`, `POST /sales/members`, `PATCH /sales/members/:userId` (never record ops on `users`; `409 LAST_SUPER` shown inline). Pipelines page: one pipeline per business, edit only (no create/delete; the server returns `READ_ONLY`).

### 4.3 Real clock + demo offset (D-clock)

`clock.ts`: `now() = Date.now() + serverSkewMs + offsetMinutes * 60000`, where `serverSkewMs = Date.parse(serverNow) - Date.now()` from each bootstrap/poll response and `offsetMinutes` is `settings/clock.data.offsetMinutes` (default 0; admin in any business can change it; refreshed by `clockOffsetMinutes` on each poll). `F.now()`, `F.today()` and Q selectors read this. When offset != 0, `ClockBanner` shows "Demo clock: +3d 4h" in the Topbar. A 60s interval bumps a `useNow()` subscription for overdue/due-today rendering.

### 4.4 Engine lease client

Engine (tick/runEngine/exec) is ported verbatim into `engine/`. Leases are **per business**. `engine/lease.ts`: `sessionId = crypto.randomUUID()` per tab; every tab calls `POST /sales/engine/lease {sessionId, businessIds}` (the businesses where `me.permissions[b].edit`) every `renewEveryMs` (15 s, TTL 45 s) and gets `{leases: [{businessId, held, expiresAt, holder?}]}`; a non-holder takes over automatically after expiry. `tick` (every 30 s) runs only for businesses with `held: true`. On `pagehide`: `POST /sales/engine/lease/release {sessionId}` via `fetch(..., {keepalive: true})` (not `sendBeacon`, which cannot send the Bearer header). Engine writes go through `Act` but are committed with origin `engine` and flushed immediately in their own batch with `engine: {sessionId, businessIds}`, after first flushing pending user ops; they are never mixed with user ops. `409 LEASE_LOST` -> nothing was applied: stop the engine for those businesses, roll the engine's local changes back, re-acquire. Failure to reach the lease endpoint means "not held" (engine does not run), shown as "Automations paused" in the topbar, never a silent run. Demo Control Centre shows "Sequences are being run by <holder.name>".

### 4.5 AI client

`ai/client.ts` exports the same function names as the prototype `AI` but async, mapped per contract section 8: `classify` -> `POST /sales/ai/classify`, `draft` -> `/sales/ai/draft` (purpose `'intro' | 'follow' | 'stale'`), `suggestReply` -> `/sales/ai/reply-suggest`, `meetingActions` -> `/sales/ai/meeting-recap`, `copilot` -> `/sales/ai/copilot`, `research` -> `/sales/ai/research` (narrative from `inference`, facts kept deterministic). `meetingBrief` has no endpoint and stays local. On `mode: 'stub'`, a 502 (`AI_PROVIDER_ERROR`/`AI_BAD_OUTPUT`) or a network error it falls back to the ported deterministic helper and marks the result `source: 'llm' | 'stub' | 'fallback' | 'refused'` (the server's `mode`, or `'fallback'` when the client fell back). There is no 501. `bootstrap.ai.enabled === false` shows the "AI not configured" badge before any call. A `<AiBadge source>` kit component renders the label. Minimal personal data: request bodies carry only the fields the tool needs (ids resolved server-side where possible). Insights, risk and cross-sell stay synchronous rules code in `ai/rules.ts`.

## 8. CSS isolation and fonts

- All prototype CSS goes into `sales.css` with every selector prefixed `.sos`. `:root` vars become `.sos`; dark theme is `.sos[data-theme="dark"]` driven by local session theme (the admin site's own theme is not read or modified).
- The root `<div className="sos">` wraps the Shell and all overlays; modals, drawers and toasts render inside `.sos` (no portals to body, or portal into a `.sos` container) so styles apply and nothing leaks.
- Tailwind preflight is global and resets headings, buttons, links, images, lists. Compensation: a `.sos` reset block at the top of `sales.css` restoring prototype defaults (`.sos button`, `.sos h1..h6`, `.sos a`, `.sos img`, `.sos ul`) because the prototype assumed no reset. Generic prototype class names (`.card`, `.btn`, `.badge`, `.table`) collide with Tailwind utilities and any admin CSS, hence the scope prefix; Tailwind utilities are not used inside `.sos`.
- No inheritance from admin: `.sos { all: initial; display:block; ... }` is deliberately NOT used (breaks children); instead `.sos` sets explicit font-family, color, background, line-height, font-size and box-sizing.
- `index.css` global rules (body styles) are untouched. `sales.css` is imported only in `sales/index.tsx`, so it ships in the lazy chunk.
- Fonts: woff2 files from the prototype bundle, latin and latin-ext subsets, `font-display: swap`, declared in `fonts.css` with relative urls; no Google Fonts requests. Verify in the browser network panel that no third-party font request occurs.
- Check: prototype uses `100vh` layouts and `position: fixed` overlays; the admin site has its own header, so the Shell uses `min-height: calc(100vh - <admin header>)` or takes over full viewport with `position: fixed; inset: 0` (decided in foundation after viewing AdminNav height).

## 10. Test and verification plan

Repo state: Vite 8, React 19, TS ~6, ESLint flat config, no test runner. Commands (to be run by the implementer; none run for this document): `npx tsc -b`, `npm run lint`, `npm run build`.

3. Chunk check: `dist/assets` shows a separate sales chunk, the demo chunk, and the admin entry does not grow by the sales code; fonts present as hashed assets.
4. Browser golden paths (against a local API with bootstrapped businesses, empty data), checking no console errors and no failed requests:

   - Create company, contact, deal; move deal stage (stage-check modal); won/lost modals; refresh and confirm persistence (record sync round trip).
   - Two browsers: edit different fields on the same record -> merged silently; same field -> conflict toast and rollback; delete in one, edit in the other -> deleted banner.
   - Offline: DevTools offline, edit, banner shows queued count, restore, queue drains.
   - Sequence create/enrol and engine lease (only one tab holds it); inbox classify with no AI key shows labelled stub/fallback.
   - Viewer role: all write controls disabled; non-member sees no-access state.

   - Style isolation: compare an admin page before and after visiting Sales (no style changes); dark theme toggled in Sales does not change admin.
   - Mobile width (390px): no horizontal page scroll.
5. Unit tests: pure-logic modules are testable without UI (`data/commit.ts` diff, `conflicts.ts`, `clock.ts`, `ids.ts`, `Q.ts`, `F.ts`, engine `tick`). - `ids.ts`: 10k ids unique, prefix by type.
- `Q`/`F`: ported selectors against small hand-built fixtures (not seed content).

Error and rescue

| Codepath | What can fail | Rescue | User sees |
|---|---|---|---|
| initial load `/sales/bootstrap` | 401 / 403 / network | redirect / no-access state / retry panel | clear state, never blank |
| record load | network, 5xx | retry with backoff, Retry button | error panel with Retry |
| batch push | network | queue to IndexedDB, replay | "Offline, N changes queued" |
| batch push | op `rejected` ROLE_REQUIRED etc. (HTTP 200) | rollback, drop op | "You don't have permission" toast |
| batch push | op `conflict` field (HTTP 200) | roll back clashing paths, prompt Keep mine / Keep theirs | conflict prompt |
| batch push | op `conflict` deleted | drop ops, mark deleted, optional Restore | deleted banner |
| batch push | 409 LEASE_LOST (engine batch) | roll back engine ops, stop engine, re-acquire | "Automations paused" until re-held |
| batch push | 413 | re-chunk smaller | invisible |
| IndexedDB | unavailable/quota | memory-only queue, log once | banner: "changes won't survive a reload" |
| poll | network | skip tick, backoff | SyncBanner offline/error |
| engine lease | endpoint unreachable | engine does not run | topbar indicator "Automations paused" |
| AI call | stub (200) / 502 / network | deterministic fallback | AiBadge labelled source |
| demo chunk load | network | toast with retry | "Couldn't load demo tools" |
| lazy sales chunk | network | route-level error boundary | "Couldn't load Sales, reload" |

Shadow paths (happy / nil / empty / error), applied to: store hydration (records present / `me` missing / zero records -> empty states / fetch fails -> error panel), mutation commit (valid / unknown id -> no-op logged / no diff -> no request / push fails -> queued), selectors (missing foreign key -> render "Unknown", not crash; this is common because the prototype assumed full seed), forms (valid / required missing / empty list / server rejects -> inline plus toast).

Observability: a `sales/log.ts` helper `logSales(op, ctx, err)` writes `console.error('[sales] <op> failed', {ids, status, err})`; no empty catch blocks (lint rule `no-empty` already in recommended; scoped override keeps it on for ported files). Sync state exposes counters (queued, last success time) shown in a hidden debug popover from the SyncBanner.

Performance: lazy chunk for `/admin/sales` plus separate chunk per heavy page is optional (units may use `lazy` inside their `units/uN.ts`); store updates notify via `useSyncExternalStore` with selector hooks (`useStoreSelector(fn, isEqual)`) to avoid re-rendering the whole app on every commit (prototype re-rendered globally); kanban and long tables virtualise only if lists over about 500 rows (not required by decisions, so deferred); polling pauses on `document.hidden`; indexes are rebuilt incrementally for touched collections only.
